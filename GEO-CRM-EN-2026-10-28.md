- Aucune règle supplémentaire d’autorisation d’entraînement ajoutée. Le groupe générique de `robots.txt` permet toujours l’exploration publique ; l’API reste exclue.
- Les tarifs monétaires proviennent du catalogue partagé existant. Le catalogue de prix n’a pas été modifié.
- Aucun `sameAs` ajouté sans profil officiel vérifié.

`llms.txt` est une synthèse facultative. Ce fichier n’est pas présenté comme un facteur de classement universel. La priorité reste un contenu utile, accessible et vérifiable : [Google, fonctionnalités IA et site web](https://developers.google.com/search/docs/appearance/ai-features). Les agents de recherche et d’entraînement ont des rôles distincts : [OpenAI, robots officiels](https://developers.openai.com/api/docs/bots), [Anthropic, robots et contrôles d’exploration](https://support.claude.com/en/articles/8896518-does-anthropic-crawl-data-from-the-web-and-how-can-site-owners-block-the-crawler). La documentation de [la recherche web xAI](https://docs.x.ai/developers/tools/web-search) ne justifie pas d’inventer un robot « Grok » ou une garantie d’apparition.

## Mesure des demandes issues des IA

- Sources autorisées : `chatgpt`, `claude`, `gemini`, `grok`, `copilot`, `perplexity`, sinon `unknown`.
- Détection par domaines exacts ou valeurs `utm_source` reconnues. Les faux domaines et les valeurs arbitraires sont exclus. Une campagne payante/e-mail conserve sa catégorie de campagne.
- Un clic Google ou Bing classique n’est pas présenté comme un clic provenant d’une réponse IA.
- Enregistrement uniquement après consentement ; première page publique conservée pendant la session ; suppression lors du refus.
- Aucun paramètre d’URL, fragment, conversation IA, e-mail, téléphone ou texte de formulaire dans cette attribution.
- Événements `ai_referral`, puis paramètres `ai_source` et `landing_language` sur les événements de conversion existants. `generate_lead` reste déclenché après confirmation d’une demande enregistrée.
- La source détaillée accompagne le champ d’origine déjà transmis au CRM. Le libellé existant est conservé pour les anciennes sessions sans source détaillée.
- Dans GA4, créer si nécessaire les dimensions personnalisées de portée événement `ai_source` et `landing_language` pour les exploiter dans les rapports. Aucun accès de configuration GA4 n’a été modifié.

Pour mesurer les visites, utiliser les sessions ou utilisateurs GA4 filtrés par source, et non le nombre brut d’événements `ai_referral` : cette information peut accompagner plusieurs pages d’une session. Pour mesurer les demandes, utiliser `generate_lead`, déclenché après confirmation, et la source conservée dans le CRM.

Une source référente ou une balise de campagne est un indice d’attribution. Elle ne prouve pas que l’entreprise a été citée dans une réponse IA. Les applications qui ne transmettent aucune origine resteront partiellement non attribuées.

## Validation

La construction, les contrôles du HTML et du sitemap ainsi que les tests fonctionnels ont réussi dans [GitHub Actions](https://github.com/ProjetMario/FLEXWEB/actions/runs/40702916001). Le contrôle HTTP de l’aperçu est également passé. [Rapport technique local de validation](.cms/geo-evidence/geo-validation.json).

- 21 172 documents construits par Astro, dont les pages privées/non indexables et les endpoints statiques.
- 102 tests réussis : 84 tests SEO/GEO et 18 tests de formulaire, analytics et proxy.
- 22 pages stratégiques de l’aperçu répondent en HTTP 200, ainsi que les fichiers robots et les synthèses texte.
- Les sondes HTTP utilisant les noms des agents de recherche officiels ont reçu un HTTP 200. Ce test ne prouve pas une visite réelle de ces robots.
- Une URL inexistante renvoie bien HTTP 404 avec `noindex`.
- 20 604 URL de sitemap : les 20 594 URL de production conservées, plus 10 nouvelles pages.
- 16 sous-sitemaps ; XML validé par un parseur XML.
- Redirections publiques vérifiées : HTTP vers HTTPS et `www` vers `https://flex-web.fr/`, en 301.
- 18 pages vérifiées pour les canoniques, langues et liens réciproques.
- 11 pages stratégiques contrôlées en navigateur à 375, 768 et 1 440 pixels, avec menu mobile et FAQ.
- Les tests d’envoi de devis utilisent des requêtes simulées et bloquent les services externes : aucune demande commerciale réelle n’a été créée.

Commandes de validation exécutées avec succès dans GitHub Actions :

```sh
npm run build
node scripts/check-seo.mjs
node scripts/seo/quality.mjs --enforce-release
node scripts/seo/audit-territorial-publication.mjs
GEO_BASELINE_FILE=.cms/geo-baseline.json node scripts/geo/validate.mjs
python3 scripts/geo/check-xml.py
node --import tsx --test tests/geo/*.test.* tests/seo/*.test.*
node --test tests/quote-flow.test.mjs tests/analytics.test.mjs tests/automation-proxy.test.mjs
node scripts/geo/verify-preview.mjs
```

Le typage global `npm run astro -- check` n’est pas passant dans cet environnement : il inclut aussi les applications et tests du dépôt, avec notamment des déclarations Node manquantes. Il n’est pas utilisé comme preuve de validation. Les contrôles de compilation, de HTML émis, de formulaires simulés, de consentement et de rendu responsive constituent les vérifications de cette livraison.

Le disque local a interrompu l’installation de dépendances et une seconde compilation. Les dépendances existantes ont été réutilisées, et seul le répertoire de compilation incomplet créé pour ce travail a été effacé. Le contrôle final et le déploiement de l’aperçu sont exécutés dans GitHub Actions, sans réactiver les builds Netlify ni modifier la production.
